# 中心四周期保留与查询性能

用户已批准四周期保留、定时精简、按需加载及中心性能优化。本次不改变 Mac 上报协议，不重发 v0.15.1 Mac 资产；中心结构为 v4，正式新版本尚未指定。

## 数据与查询

- 按可靠账号、Provider、limit、窗口类型及时长分组；未关联观测继续按设备与 local_scope 隔离，不按邮箱合并。
- 每个窗口保留最后有效值所属周期和最近其他已观测周期，合计最多四个。没有新观测时保留原值和时间，不制造新周期。无法归入有效周期的异常证据单独保留，不根据未知 reset 推断删除归属。
- 首屏 `/api/v1/quotas/accounts` 只读账号；`/api/v1/quotas?view=summary` 读取来源/reset/有效性/零值状态的真实首末证据并使用共享仲裁，返回当前快照，不读取完整观测数组或统计历史数量。未来时间和无效 reset 分区，避免排挤最后有效值。
- `/api/v1/quotas/pace?window_key=...` 只加载选中窗口的四周期证据；预测仍使用完整当前周期。图表每周期最多 512 个真实端点/极值，显示抽稀不改变预测输入，不插值生成采样。
- 来源证据展开后请求 `view=evidence&window_key=...&page=1&limit=20`，每次最多返回 100 条。精确观测数量在展开后的响应提供；后端在该窗口的保留周期内仲裁，不扫描所有账号历史；分页响应不携带完整周期观测 ID 清单。当前实现仍在选中窗口内完成投影后分页，尚未将全部仲裁逻辑下推 SQL。
- 较大的额度/统计/价目 GET 响应使用 gzip；配对、会话凭证、上报与 metrics 保持现有路径和鉴权。业务 API 继续仅管理员可读，Cookie 与 CSRF/Origin 规则不变。

## 后台精简与补传

`server.quotaMaintenance` 默认关闭。备份后显式开启：启动时和每小时执行，单轮两分钟截止、与服务生命周期一起取消。结束周期中的连续相同额度/reset/有效性按精确设备、来源、scope、历史归属分组，保留每段首末；当前最后有效值所在周期保留完整证据。不同额度、reset 与来源不合并。

移除原始行与写入 `pulse_retired_observations` 在同一事务完成，锁定相关 collector 行与上报串行。退役标记只保存 ID、不可变事实摘要与精简时间；原样全量补传被确认但不恢复原始行，修改同 ID 的事实返回冲突。身份关联字段不进入摘要，后续显式关联仍遵循既有契约。幂等标记继续保留，因此原始观测减少并不代表所有历史元数据消失。

## 统计投影

`pulse_session_capsules` 为每个来源及 canonical 保存完成/删除状态、贡献 ID 集合摘要、TPS 与缓存指标。上报事务同步写入；旧库每秒分批补建，每批上下文三十秒，补建完成后停止扫描；新上报在同一事务内维护投影。只插入缺失项，避免覆盖并发上报的新投影。

全局统计读取来源元数据和结构化用量/调用表；Session 指标读取 capsule，不反复传输与解析大型贡献/调用 JSON。缺失来源投影时使用既有读取逻辑，补建完成后稳定使用小型投影。按单台采集机过滤的统计仍需要该来源的完整快照仲裁，保留设备范围的正确性；该路径尚未完成结构化独立投影。

## 部署与回滚

先进行数据库备份及独立恢复演练，再部署 DEV。生产切换前停止接收并备份完整 v3 状态，同时保留旧配置与二进制；启动自动升级 v4 后启用维护，并等待派生摘要补建完成。旧 SQL/发布资产保持不可变。

回滚需要停止服务，将升级前备份恢复到专用空库（恢复流程撤销旧授权），以 v3 配置/二进制连接恢复库并重新配对。不能直接用 v3 二进制读取 v4 标记。恢复到备份时间点会丢失切换后的事实，因此实际故障优先在 v4 保留数据修复，不自动清空当前库。
