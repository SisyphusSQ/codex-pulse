# 中心统计接口与 SQL 性能

TOO-526 面向全部中心路由与仓库 SQL：降低首屏等待，同时保留 NULL/真实零、任意精度、历史价格、自然日/DST、来源去重与权限。用户接受重统计一至两分钟延迟，详细契约见 [统计 API](../../../../api/statistics.md)，现场结果见 [性能验收](../../../test/too-526-performance.md)。

## 查询策略

年度仅累计年度总量、日桶和覆盖；usage 仅累计精确总量、平台、模型日桶与成本，不再计算会话排行和小时分布。会话列表只计算会话，项目列表只计算项目；详情保留自身所需趋势、模型、指标与采集来源。项目覆盖/来源按一次会话遍历归组，避免项目数乘会话数的重复遍历。按本地日边界复用日期字符串，边界仍以 AddDate 计算。

模型谓词下推到参数化 SQL；unknown 对应 NULL、空串及字面 unknown，Go 再执行同口径过滤。搜索匹配少于等于 4096 会话时下推会话键，宽搜索保留原流式路径与预算。目录 SQL 先按会话/模型/价格证据去重再连接，减少中间连接行。保留既有全年 HASH hint；不能把 SeekDB 现场计划推广成其他数据库必须使用同样索引。

来源快照在同一只读事务内联查来源、分片归属与分片表，按 `session_key,id,part_index` 一次流式读取。内联正文逐行交付，分片仅按当前来源有界收集，并与普通解引用共用清单、分片长度/顺序和 SHA-256 校验；流中不再嵌套查询数据库。来源按会话连续交付，全部 Home 合并后再仲裁，不同机器副本保持独立。仲裁不重复比较选中来源与自身。不得恢复每 8 条重复执行会话筛选的全量扫描，或只按来源 ID 排序。

没有证据支持新增索引：事实按时间/会话的既有复合索引、来源与指标按会话/客户端主键、接收按批次幂等唯一键已经覆盖对应选择条件。年度大量事实必须读出并由精确业务算法聚合，更多相同前缀索引不会消除扫描与 CPU 计算。64 MiB/32 条目的 Server 缓存把这些计算移至有界后台，不在数据库重复维护另一套业务总量。

## 全 SQL 审查范围

| 仓库 / SQL 家族 | 现场结论与处理 |
| --- | --- |
| statistics：Session/Project/Client/Device、来源元数据、用量流、无时间事实、指标 capsule | 日期/归属筛选与既有索引保留；年度 HASH 路径；模型和窄搜索下推；避免全局 payload 和无用聚合 |
| catalog：模型、历史价格 DISTINCT | 先按 Session 去重，现场结果摘要一致且两轮更快 |
| quota：账号、最新窗口、历史周期、节奏 | 既有窗口筛选、最近四周期和观测精简继续使用；账号快读不缓存，较大历史只按选中窗口读取 |
| access：配对、凭证、CSRF、授权列表、重命名、撤销 | 主键/秘密摘要唯一键和条件更新；实时鉴权与撤销不缓存 |
| reporting：receipt、chunk、session/project/account、fact/source/capsule、同步、关联、精简摘要 | 批次唯一键、复合主键、有界批量和事务锁保留；不改变幂等或来源仲裁 |
| subscription：读写与乐观 revision | 账号点读、条件更新保留；不用陈旧缓存控制写入 |
| schema / upgrade / migrate、备份 SQL | 是部署/恢复路径，保持 v4 校验与一致备份，没有本次 DDL |

审查通读全部 SQL 家族与已有表结构，现场 EXPLAIN/对照集中于慢统计和目录查询；未声称每条点读/写入都单独执行 EXPLAIN。无需为了“全优化”修改已经较快的点读或删除正确性约束。

## 失败与验证

后台受 Fx 生命周期、单工作者、deadline、条数与字节预算约束；错误保留最后成功数据并暴露状态，冷失败继续报错。缓存不包含凭证或原始 payload，HTTP 管理权限仍在命中前验证。卡片懒加载，查询状态互相独立，前端不重算统计。验证包括精确结果对照、隔离全部路由成功/错误/鉴权场景、缓存并发与刷新失败、现场各读接口与部署后缓存刷新。

年度卡片五项展示见 [TOO-527 验收](../../../test/too-527-annual-metrics.md)，新增峰值与连续天数直接使用 annual.heatmap_activity，不增加 SQL 或前端重算。

## TOO-697 后台负载调整

年度改为访问期间每五分钟刷新；机器来源维持访问期间一分钟。两者取消无浏览预热，超过五分钟无访问暂停；默认今日 usage/current 继续一分钟预热。缓存 metadata 按实际间隔设置 refresh_after_ms，超过两倍间隔标记 stale；失败仍保留最后成功快照。额度 Web 自动读取改为一分钟，手动刷新入口保留。首次访问年度/来源仍需真实冷计算。

本轮 schema v7 为发布租约、清理排序、来源任务和 generation 判断增加四个有实际调用方的索引，不能据此声称年度计算或版本回收不再扫描存量。旧 TOO-526 的无新增索引结论只描述当时范围。验收见 [TOO-697](../../../test/too-697-server-sql-scheduling.md)。

TOO-698 继续审查年度与来源历史读取，保留上述精确业务口径；实际优化集中在积压回收的重复历史候选查找，无新增统计 SQL 或 DDL。见 [回收策略](../../../../../docs/design/details/multi-machine-reporting/center-query-performance.md#too-698-历史回收扫描)与 [验收](../../../test/too-698-history-scan.md)。

## TOO-699 统计投影精简

年度及其他结构化统计流只读取聚合消费的数值、定价与归属字段，不再传输 contribution_id/position；无时间事实只读取 session_key/model。没有 DISTINCT、提前截断或改变版本筛选，数值相同的不同事实仍逐条计数，NULL/零和精确整数口径不变。宽年度范围仍可选择全扫描，精简的是返回列与 Go 扫描开销，不承诺消除必要历史读取。

机器来源总量复用现有 projection 聚合，仅累计总量与覆盖，不建立未返回的日桶。总量内部仍以当地自然日、模型、历史费率分组计价，不能把删除日桶误解为跨日合并舍入。全部 Home 的有序读取、分片校验与 DecideSnapshot 仲裁不变，缓存刷新和失效策略不变。实测见 [TOO-699](../../../test/too-699-statistics-history.md)。

来源及按机器统计使用 json.UnmarshalRead 从字符串流严格解码，避免先将整个正文复制成字节数组；仍拒绝未知字段、重复键、非法 UTF-8 和尾随 JSON，且完整解析贡献与调用字段后再执行原有统计路径，不跳过验证。
