# TOO-699 年度与来源统计投影优化

日期：2026-11-08；[TOO-699](https://linear.app/sisyphus-sq/issue/TOO-699)。仅 Server，schema 保持 v7，无 DDL、新依赖或客户端改动。

## 实现与准确性边界

- 结构化用量流不再返回聚合未使用的 contribution_id/position；无时间事实流只返回 session_key/model。保留日期、模型、会话、已发布版本筛选、全部实际消费字段及只读事务；不使用 DISTINCT，数值相同的不同事实仍逐条计数。
- 来源总量采用现有 projection 分支，去掉未返回的日桶聚合。总量内部仍按当地自然日、模型、历史费率分组，保持每天舍入；全部 Home、副本包含/冲突/删除仲裁、分片校验与读取顺序不变。
- 年度大量事实仍需读取；来源仲裁不能以采集时间过滤贡献。未新增持久汇总表、索引、缓存策略或额外降频。

## 开发验证

- statistics repository/service 聚焦测试通过（1.453s / 2.236s），两个受影响包 vet 通过；Web 类型检查/Vite 与 Server release 构建通过。
- 新测试覆盖已发布/旧代际/旧内联事实排除、相同数值的独立事实、全部统计字段映射、NULL 和无时间覆盖；来源测试对比旧日桶路径与新总量路径，覆盖跨 DST 自然日分别舍入、超过浮点精度整数、真零、未知模型/数值、时间边界及筛选。已有多 Home、跨机器、冲突/删除与分片错误测试同时通过。
- 5 万条合成事实、每种模式三轮基准：旧聚合 19.65–21.94 ms、约 9.55 MB/408415 allocations；新聚合 11.75–11.93 ms、约 4.96 MB/253180 allocations。仅衡量聚合，不代表正文解码、仲裁和接口端到端比例。

## 实际数据库只读对照

现场为本机 SeekDB 1.2.0 / MySQL 兼容协议，不等同独立 MySQL 8.4。每个物理事实流的新旧 SELECT 在同一个只读一致快照中执行；对实际消费字段排序后做 SHA-256 对照，不保存真实明细至源码。

| 事实流 | 返回行数 | 旧文本字节 | 新文本字节 | 字段对照 |
| --- | ---: | ---: | ---: | --- |
| 未采用分代发布的事实 | 527162 | 144232354 | 108048359 | 相同 |
| 当前已发布代际 | 173964 | 47941541 | 35780600 | 相同 |

合计 701126 行，文本输出从 192173895 降至 143828959 字节，减少 48344936 字节（约 25.16%）。这是 MySQL CLI 文本结果体积，不是线缆流量或固定延迟保证。各物理流使用各自一致快照，不宣称两次事务共同组成原子的全库时点。

新旧执行计划保持宽范围 HASH 与全扫描：该年度范围需要绝大多数事实，额外同前缀索引不能避免取回必要数值。来源仍为来源/归属/分片的一次有序联查，保持完整副本参与仲裁；不为消除全扫描字样强制索引。
