# source-usage 来源扫描回归修复（2026-10-13）

## 原因与修复

TOO-582 将来源读取改为每 8 条分页并仅按来源 ID 排序。真实规模下重复筛选、读取超过统计计算的 10 秒期限；来源 ID 又不能保证同会话副本连续，导致调用方提前仲裁并重复累计。

最终修复在同一只读快照内联查来源、分片归属与分片表，按 `session_key,id,part_index` 一次流式读取。内联正文逐行交付；分片按当前来源有界收集，与普通解引用共用清单、分片长度/顺序和 SHA-256 校验，流中不嵌套数据库查询。仲裁跳过选中来源与自身的重复事实索引和反射比较，不改变来源选择与冲突语义。没有数据库结构、协议或超时配置变更。
