# TOO-698 历史扫描优化验收

日期：2026-11-08；[TOO-698](https://linear.app/sisyphus-sq/issue/TOO-698)。本次仅 Server 回收 SQL，schema 仍为 v7，无 DDL、无新依赖、无原生客户端更新。目标数据库为 SQMC04 SeekDB 1.2.0 的 MySQL 兼容协议，不等同独立 MySQL 8.4。

## 结论与实现

原逻辑每回收 250 行就重新跨历史反连接查找候选；新逻辑保留这一步和跨代际批次，满批后沿末行的 generation/session_key 主键前缀连续清理。定向读取只取 contribution_id，删除固定代际/会话与有界 ID 列表；前缀清完再回到全局候选。稀疏的小代际不逐个查找，仍按原批次合并。

所有读和删除保留活跃租约与当前发布指针条件；每批最多 250 行、五秒总预算、无进展退出和一分钟失败重试均保留。正文回收、所有者与一小时保护不变。空闲候选探测仍需扫描存量，未引入持久目录或另一套派生真相。

年度和来源查询已继续审查：年度已有日期范围/已发布指针过滤，精确费用与未知值仍需要真实事实；按机器的来源统计必须跨 Home 仲裁，采集时间不是贡献时间，不能用最近采集时间提前裁掉历史快照。未新增没有收益证据的索引、聚合缓存或回填流程。

## 隔离验证

- 受影响 reporting_srv 包通过，reporting_repo 编译通过（该包无独立测试文件）；聚焦回收/轮询 race 与受影响包 vet 通过。Web 类型检查/Vite 与 Server 发行构建通过。
- 保留现有有效版本、活跃租约、近期及有所有者正文保护测试；增加跨会话多批、503 个单行代际、删除前出现发布指针/租约以及定向删除被取消的覆盖。
- 同代际跨两个会话的 1502 行回收不随每个删除批次重复扫描历史；503 个单行代际仍至多三次全局候选查询，没有按 503 个代际逐个扫历史。
- 独立合成 SeekDB 库：100000 行有效数据 + 10000 行孤立版本。真实 repository 与旧版函数交错运行，四次均完整回收孤立版本并保留全部有效行。每次删除 40 批；旧版历史候选查询 41 次，新版 2 次。整体 Query 回调数旧 124、新 126，不能声称所有 SQL 次数都下降。
- 最终实现交错样本：新版 4784 / 2665 ms，旧版 4171 / 3426 ms，各次都在一轮五秒预算内完成。共享主机和删除写入使总耗时波动，区间重叠，不承诺固定延迟收益。
- 独立查询对照均返回 250 行：旧查询审计 MEMSTORE_READ_ROW_COUNT=250、SSSTORE_READ_ROW_COUNT=100004、ELAPSED_TIME=48253 微秒；定向查询为 256、0、9658 微秒。该次由约 10 万读行降至 256，证明重复候选读取工作量减少；这是合成样本，不推广成生产固定百分比。
- SeekDB EXPLAIN：定向读取走 generation/session_key 索引范围，定向删除走主键 TABLE GET；简单 DISTINCT/GROUP BY generation 仍全扫约 20 万历史行，未采用。
