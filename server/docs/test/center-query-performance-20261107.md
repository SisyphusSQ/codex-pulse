# 2026-11-07 中心回收与额度查询性能

在 SQMC04 完成两轮代码优化、聚焦验证及开发实例部署。代码基于主干 d15da7f，分支为 suqing/server-query-performance。当前开发版本为 dev-query-perf-20261107-r4，第二轮对照见文末。

## 改动与边界

- 发布任务仍按秒轮询。版本回收改为启动时执行，随后每轮结束至少一分钟才再次执行；每轮共用五秒预算，分批消化积压。候选版本只读主键，删除时重新检查发布指针和活跃租约，过期正文继续检查所有者。
- 额度首末证据先计算端点 ID，再在同一 SQL 与读快照中通过 JOIN 按主键读回。通过行序号与分区总行数选择首末，保留零值、异常时间、无效 reset、来源和历史归属的分区语义。
- 当前周期 Token 在数据库中按整数商及余数汇总，再还原为任意精度整数。保留 200000 条事实预算、设备来源过滤、已记录零值及能力未知的区别。
- 节奏读取跳过响应不用的 Credits、Token 汇总和设备名称；周期、预测、完整当前周期输入与每周期 512 个显示点的规则沿用原实现。
- 周期回收仍需要扫描存量版本。此次降低空闲扫描频率，未引入持久回收队列或新结构迁移。

## 同引擎大数据对照

使用本机 SeekDB 1.2.0.0 的独立临时库及合成事实，包含 2 个账号、4 个窗口、156000 条额度观测、80000 条账号 Token 事实和 200000 条已发布快照版本。使用相同数据、固定求值时间、相同主干依赖，分别编译改前与改后的业务入口。每个指标先预热 2 次，再连续测量 9 次，顺序执行。

| 业务入口 | 改前中位数 | 改后中位数 | 变化 |
| --- | ---: | ---: | ---: |
| 额度摘要 | 2023.70 ms | 1390.47 ms | 降低约 31% |
| 选中周窗口的节奏 | 1157.75 ms | 839.03 ms | 降低约 28% |

上述为 service 加真实数据库往返耗时，未计 HTTP、浏览器和跨机器网络。机器同时承载其他服务，九次样本不能代表稳定分位数。两份完整摘要与节奏响应在固定求值时间下逐字段相等。

单独对相同窗口测量端点 SQL，原全字段双向排序中位数 470.66 ms，只计算 ID 的双向排序为 320.71 ms，ID 加同向序号/分区计数为 276.11 ms。计划仍包含窗口计算和排序，不声称已消除全部排序。

另用隔离 SQLite 合成数据检查兼容性，17 次样本的摘要中位数 1904.15 → 1434.23 ms，节奏 831.96 → 693.11 ms。这只能作为开发测试证据。

## 首轮开发实例回读

开发实例使用原私有配置和数据库。部署版本为 dev-query-perf-20261107-r3，schema 仍为 6；health、ready 和受保护的额度/节奏接口均返回 200。使用临时管理员会话进行实际 HTTP 请求，完成后撤销。

开发存量只有 220 条额度观测，且没有活跃 Token 周期。17 次实际 HTTP 样本的摘要中位数为 8.33 → 14.75 ms，节奏为 7.47 → 9.41 ms。小窗口未体现耗时收益；端点主键回读增加一次或多次数据库往返，换取大窗口更少的排序与传输开销。部署前后构建版本及共享数据库负载也不同，不能将该组样本视作隔离的代码性能对照。

SQL Audit 在原开发实例的 12 秒内观测到 12 次版本回收扫描，新调度的 68 秒内观测到 2 次，符合按分钟调度。新调度测试同时确认发布轮询持续运行。

首次部署发现开发库既有 schema v6 摘要来自 Windows CRLF SQL 字节，本机源码为 LF。已立即恢复原实例，再以构建 overlay 引用同内容的 CRLF MySQL SQL 文件，得到与原库一致的摘要并成功启动。SQL 源文件和数据库版本标记均未改写。该开发包使用既有 CRLF 摘要，普通 LF 构建不能直接替换此开发库的构建。

开发库部署前已完成私有一致性备份。原始备份、测量程序、响应比对、SQL 计划及日志保存在忽略的 server/.artifacts/query-perf/，不提交。其中的临时性能库在验证后删除，包含凭据的临时客户端配置和管理员会话材料在使用后清理。

## 回归与自查

已通过 quota_repo、quota_srv、reporting_srv 与 HTTP 包测试，以及回收调度和删除保护场景的聚焦 race；受影响 repository/service 包的 go vet 通过。覆盖旧端点 SQL 等价性、同时间观测、无效与未来证据、来源过滤、超过单批的端点读回、超 int64 总量及事实条数预算、回收积压、租约保护和删除前重新发布。

较大范围的 service race 尝试因耗时收窄为回收相关场景；不将该尝试作为全部 service race 已通过的证据。未运行全仓长测、CI 或正式环境验收。

安全自查确认管理员权限、参数化查询、来源隔离、读快照及资源预算仍由原责任层处理，回收删除增加了发布指针复核，本次改动及脱敏记录不含真实凭据、原始业务内容或私有备份。

## 第二轮，减少小窗口往返

端点 ID 派生表与原始观测按主键 JOIN，一条 SQL 完成窗口端点计算、记录读回与排序。移除了 Go 端分批绑定 ID 和再次排序。端点超过 100000 时仍返回原预算错误；测试中的 2048 条混合来源、有效性、同时间和异常时间记录，结果与原全字段双向排序逐条一致，并断言每次 Headers 实际只执行一次查询，排除 GORM 构造子查询时的 DryRun 回调。

SeekDB 曾将很少的端点高估为数万行，普通 JOIN 选择了观测表全扫。使用 LEADING / USE_NL 提示，使端点驱动主键 TABLE GET。SQLite 接受该 SQL 并忽略提示，已有 SQLite 回归通过。独立 MySQL 8 的性能尚未实测。[OceanBase 连接提示说明](https://docs.oceanbase.com/oceanbase-database/V4.4.2-optimizer-hint)

配对 HTTP 测量在后台大数据测量完成后进行，依次启动 r3 与 r4，使用相同私有配置、数据库、临时管理员会话和请求参数。每项预热 2 次后测量 17 次，结束恢复并确认 r4 ready。

| 开发小数据 HTTP | r3 中位数 | r4 中位数 | r3 / r4 样本 p90 |
| --- | ---: | ---: | ---: |
| 额度摘要 | 11.66 ms | 7.76 ms | 17.87 / 10.18 ms |
| 选中窗口的节奏 | 8.36 ms | 6.36 ms | 12.90 / 7.91 ms |

业务层 SQL 数从摘要 7 → 5、节奏 5 → 4。这里不包含 HTTP 鉴权和事务 begin/commit。小数据仍为 220 条额度观测、935 条 Token 事实、2 个窗口，且没有活跃 Token 周期。

另在独立 SeekDB 合成库对相同的 156000 条观测、80000 条 Token 事实、200000 条版本进行固定时间对照，每项预热 2 次再测量 9 次。该轮共享主机负载高于首轮，因此仅在本轮内比较。

| 大数据业务入口 | r3 中位数 | r4 中位数 | 业务 SQL 数 |
| --- | ---: | ---: | ---: |
| 额度摘要 | 4405.76 ms | 4306.71 ms | 15 → 11 |
| 选中窗口的节奏 | 2350.65 ms | 2229.74 ms | 5 → 4 |

完整摘要与节奏响应在固定求值时间下逐字段相等。该轮摘要样本最大值超过 10 秒，不能据此承诺稳定尾延迟，也不能把不同轮次的绝对耗时直接相减。

驱动参数插值实验在配对重启后出现了摘要耗时回退，最终交付使用原有参数绑定协议，优化集中在单条 SQL 内完成端点回读。开发构建仍使用与既有 CRLF schema 摘要匹配的 overlay。相关包测试、vet、开发 health/ready 和实际 HTTP 回读通过。已对最终 GORM 生成的开发查询执行 EXPLAIN，确认端点派生表驱动 NESTED-LOOP JOIN，观测记录使用 TABLE GET。原始证据位于忽略的 server/.artifacts/query-perf/round2/。临时性能库及授权已清理，打包产物与当前 r4 实例摘要一致，正式环境未部署。
